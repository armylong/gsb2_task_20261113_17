# 本地网页采集工具

一个完全在本地运行的分页 JSON 采集工具：Python 标准库 + SQLite 后端，原生 HTML/CSS/JS 前端，
内置一个可在线改数据、切换故障场景的测试网站。**无需 pip 安装任何第三方包**，Python 3.10+ 即可运行。

## 一条命令启动

```bash
python3 run.py
```

启动后会同时拉起两个本地服务（全部监听 127.0.0.1，不访问任何外部网站）：

| 服务 | 默认地址 | 说明 |
| --- | --- | --- |
| 采集工具页面 | http://127.0.0.1:8000 | 在浏览器打开这个地址操作 |
| 内置测试网站 | http://127.0.0.1:8011/api/items | 演示用分页 JSON 接口 |

可选参数：`python3 run.py --port 9000 --test-port 9011 --data-dir ./data`

所有状态写入 `data/collector.db`（SQLite），测试网站的数据修改写入 `data/testsite.json`。
按 `Ctrl+C` 停止；再次运行 `python3 run.py` 会自动恢复未完成的轮次继续采集，不会从头另开。

## 运行自动测试

```bash
python3 tests/test_system.py
# 或
python3 -m unittest discover -s tests -v
```

8 个端到端测试用真实 HTTP 服务验证（非 mock、非写死结果）：

1. **重启续采**：暂停后“杀掉”整个程序、用同一个数据库重启，轮次和页数进度保留，继续后在原轮次内采齐，不产生新轮次
2. **同站共享限速**：两个任务同时采同一网站，6 次请求的相邻间隔共同遵守配置的最小间隔
3. **暂停继续**：暂停期间页数/记录数零增长，继续后不漏页、不重复保存记录
4. **失败轮次不误判删除**：持续 500 导致第二轮失败时，不允许做“消失”对比，第一轮完整结果仍可查看
5. **旧轮次导出冻结**：第一轮的 CSV/JSON 导出在第二轮采集后字节级不变；新增/变更/消失的编号与实际修改一一对应
6. **翻页绕回保护**：`next` 指回已采页面时自动停止，重复 id 保留最后一次内容
7. **429 遵守 Retry-After**：网站先限流后恢复，按网站允许的时间重试并采齐
8. **外站跳转拦截**：302 跳转到别的端口时整轮失败，外站数据一条都不入库

## 功能与设计说明

### 任务与轮次

- 新建任务填写：入口网址、最大并发请求数、同网站最小访问间隔、最大重试次数、结果字段配置。
- 字段配置支持嵌套路径（如 `author.name`），可自定义结果列名；记录里不存在的字段留空。
- 每个任务可以反复“再跑一轮”。每一轮都是独立快照：新一轮采集期间上一轮完整结果照常查看，
  采完后才会出现在对比里。对比按记录 `id` 给出**新增 / 内容变化 / 消失 / 未变化**清单。
- 只有 `status=completed` 的轮次才参与“消失”判断；失败、暂停、进行中的轮次不会把暂未采到的记录算成删除。

### 采集引擎（`app/engine.py`、`app/fetcher.py`）

- 每个轮次一个协调线程 + 有界线程池（大小取任务的并发设置）。
- **暂停**：通过事件通知，不再发出新请求；已经发出的请求允许处理完；恢复后从持久化的 `pending_url` 继续，不漏不重。
- **进度持久化**：每采完一页立刻把下一页地址、已访问页面、记录快照写入 SQLite（WAL 模式），
  崩溃/重启后从下一页继续。
- **去重与绕回**：同一轮同一 `id` 做 upsert（保留最后一次成功内容）；已访问 URL 唯一约束，
  `next` 绕回已采页面时整轮正常结束。
- **限速**：全进程按“协议://域名:端口”共享一个限速器，多个任务采同一网站时共同遵守，
  间隔取各任务中最严格的值。
- **重试与终止**：
  - HTTP 429 与 5xx、超时、连接失败 → 可重试，次数受“最大重试次数”限制；429 优先遵守 `Retry-After` 头，否则指数退避。
  - 404 / 401 / 403 等其他状态码、非法 JSON、缺少 `items`/`id` → 致命错误，整轮停止并写明原因。
  - 失败请求记录请求地址、状态码、尝试次数、原因，可在任务详情查看。

### 同源保护（`app/utils.py`、`app/fetcher.py`）

- 入口网址确定唯一允许来源（协议 + 域名 + 端口，默认端口归一化）。
- `next` 是相对路径时按**当前实际访问地址** `urljoin` 解析。
- `next` 指向外站、或服务端 302 跳转到外站（含端口/协议变化）→ 整轮停止并提示，外站内容不入库。

### 导出（`app/export.py`）

- CSV：`utf-8-sig`（Excel 打开中文不乱码），RFC4180 转义，字段里的逗号、引号、换行均正常保留。
- JSON：导出该轮保存的完整原始记录快照。
- 导出始终基于所选轮次的独立快照表，后续再采多少轮都不会改变旧轮次内容。

### 内置测试网站（`app/testsite.py`）

在页面“测试网站”标签可直接切换六种场景、在线增删改记录（含中文与嵌套 `author.name`）：

| 场景 | 行为 |
| --- | --- |
| `normal` | 正常分页，末页 `next=null` |
| `loop` | 记录重复 + 第 3 页 `next` 绕回第 2 页，且重复记录内容变化 |
| `ratelimit` | 前两次请求返回 429（`Retry-After: 1`），之后恢复正常 |
| `error` | 一直返回 HTTP 500 |
| `redirect` | 302 跳转到另一个端口的“外站”服务 |
| `offsite_next` | 首页正常，`next` 字段指向外站 |

推荐演示路径：`normal` 采完第一轮 → 在“测试网站”页新增一条、改一条、删一条 →
回任务页“再跑一轮” → 查看对比中的新增/变化/消失编号与修改完全对应。

## 目录结构

```
repo/
├── run.py                # 启动入口（工具 + 测试网站一起拉起）
├── app/
│   ├── db.py             # SQLite 数据访问层（任务/轮次/记录/失败请求）
│   ├── utils.py          # 同源判断、嵌套取值、按网站共享的限速器
│   ├── fetcher.py        # HTTP 抓取、跳转拦截、重试与错误分类
│   ├── engine.py         # 线程池调度、暂停恢复、重启续采、轮次生命周期
│   ├── diff.py           # 轮次对比（新增/变化/消失）
│   ├── export.py         # CSV / JSON 导出
│   ├── testsite.py       # 内置测试网站 + 外站跳转目标服务
│   └── web.py            # REST API 与静态页面服务
├── web/                  # 原生前端（index.html / styles.css / app.js）
├── tests/test_system.py  # 端到端自动测试
└── data/                 # 运行后生成：collector.db、testsite.json
```

## 主要 HTTP API

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/tasks` | 任务列表 |
| POST | `/api/tasks` | 新建任务 |
| GET | `/api/tasks/{id}` | 任务详情（含轮次列表、字段配置） |
| POST | `/api/tasks/{id}/rounds` | 开始新一轮 |
| POST | `/api/rounds/{id}/pause` `/resume` | 暂停 / 继续 |
| GET | `/api/rounds/{id}/records?page=&size=` | 轮次结果分页 |
| GET | `/api/rounds/{id}/failures` | 失败请求列表 |
| GET | `/api/rounds/{id}/diff` | 与上一完整轮次对比 |
| GET | `/api/rounds/{id}/record/{rid}` | 单条记录各轮次历史 |
| GET | `/api/rounds/{id}/export?format=csv|json` | 导出该轮快照 |
